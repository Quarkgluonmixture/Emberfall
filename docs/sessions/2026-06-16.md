## Bugfix: flickering citizens (blank animation frames)

**Symptom:** the owner reported citizens constantly flashing ("人物一直在闪")
even in calm early-game play at 1×.

**Diagnosis (probes, not guesswork):** ruled out the sim/agent layer first —
a real-frame probe sampling agent count, index→sprite remaps, per-frame
position jumps, and container alpha across days 0/9/60 and a 1.4→3.0 zoom sweep
showed **zero** count churn, jumps, or alpha toggles. The flicker was invisible
to position sampling because it was a *texture* strobe. A second probe measured
the opaque-pixel coverage of every sliced citizen animation frame and found the
cause:

- The batch-15 `citizen6_*` sheets are **incomplete art**. Walk/work/fight ship
  only **3 of 4** frame columns and rest only **1 of 2**; the trailing column is
  fully transparent. Cycling `frames[floor(phase·rate) % len]` therefore landed
  on a blank frame once per cycle → every citizen blinked to nothing.
- The **6th role row (elder) is entirely empty**, so ~1/6 of agents
  (`id % 6 === 5`) rendered nothing at all.

**Fix (`src/render/textures.ts`):** added `frameCoverage()` (cheap canvas
readback, ≤48² sample) + `pruneBlankAnims()`. At load we now drop any frame
under 2% opaque coverage and drop a role whose every state is empty; a state
that loses all frames is backfilled from the richest surviving cycle so
`frameFor()` never indexes an empty array. Applied to both `citizenVariants`
and the single-set `citizenAnims` fallback. This is the project's
"works with any subset of art missing" rule extended to *partial* sheets —
incomplete art now degrades to fewer frames/roles instead of strobing.

Post-fix coverage probe: 5 populated roles, each walk/work/fight = 3 real
frames, rest = 1, **no blank frames**. Cosmetic/render-only — zero determinism
impact.

**Follow-up (art, optional):** regenerating batch 15 with full 4-frame
walk/work/fight cycles + a real elder row would restore the dropped 4th frame
and 6th variant. Not required — the loader handles the current sheets cleanly.

**Verify:** typecheck · 64/64 vitest · lint clean · 12-shot art:shots battery
all QA passed.

## Bugfix: clipped citizens on hardware GPUs (disembodied heads / half-bodies)

**Symptom:** after the flicker fix, the owner reported citizens rendering
broken — "左侧缺失,右侧半个身子 / 有的没脑袋,有的多出来半截身子" (left clipped,
half a body on the right; some headless, some with an extra half-body),
including lone citizens, persisting through hard reloads and a fresh tab on a
never-cached port.

**Diagnosis (long hunt, all probe-driven):** ruled out, in order — stale
browser cache (server sends `Cache-Control: no-cache` + size ETag; all three
dev servers serve the byte-identical current PNG), stale JS (live module
contains `pruneBlankAnims`), an old un-grounded PNG (the grounding commit
`9783c60` had already centered every cell; current slices are clean), and DPR.
Headless (software) rendering was ALWAYS clean, which masked it. The break only
reproduced once I drove a **headed** browser on the real GPU
(AMD Radeon 890M / ANGLE D3D11): disembodied helmet heads + fragment slivers,
exactly as reported. Rendering each sliced frame as a standalone sprite was
clean (textures are fine); the live `CitizenLayer` reuses a sprite pool and
swaps each sprite's `.texture` between sub-frames of ONE shared sheet every
frame — on the hardware batcher a reused sprite then samples the wrong sub-rect.
Software batches differently, so headless never showed it.

**Fix (`src/render/textures.ts`):** `bakeStandalone()` — at load, draw each
surviving frame's sub-rect into its own canvas and make an independent
`Texture` from it (applied inside `pruneBlankAnims`'s `keep`, so both
`citizenVariants` and the `citizenAnims` fallback get standalone frames). No
shared source ⇒ no sub-rect to mis-sample. ~50 small canvas bakes at load;
render-only, zero determinism impact.

**Verify:** typecheck · 64/64 vitest · lint · 12-shot battery green; AND a
headed AMD-D3D11 repro now renders whole figures across two runs (was
fragmented before). (Software-only `art:shots` can't see this class of bug —
the headed repro is the real check.) Remaining: citizens still have no depth
sort / building collision (a citizen can stand on the tent roof) — a separate,
pre-existing limitation, not this bug.
